    本番デプロイガイド

    このガイドは、本番環境で Ralph Orchestrator を運用するためのデプロイパターンと運用 チェックリストを扱います。Ralph はアルファ品質で進化中のため、これは堅実な出発点として 扱い、自分のインフラ、リスクプロファイル、コンプライアンス要件に合わせて検証・調整して ください。

    本番前チェックリスト

    インフラの要件

    • [ ] 計算リソース
    • 最低: インスタンスあたり 2 vCPU、4GB RAM
    • 推奨: インスタンスあたり 4 vCPU、8GB RAM

    • オートスケーリングを設定（2〜10 インスタンス）

    • [ ] ストレージ

    • アプリケーションとログ用に 100GB SSD
    • データ用の別個の永続ボリューム

    • バックアップストレージを設定

    • [ ] ネットワーク

    • ロードバランサを設定
    • SSL/TLS 証明書をインストール
    • ファイアウォールルールを設定

    • DDoS 保護を有効化

    • [ ] 高可用性

    • マルチ AZ デプロイ
    • データベースのレプリケーション
    • キャッシュ用の Redis クラスタ
    • メッセージキューの冗長性

    セキュリティの要件

    • [ ] アクセス制御
    • RBAC を設定
    • サービスアカウントを作成
    • API キーをローテーション

    • 管理者アクセスに MFA を強制

    • [ ] シークレット管理

    • HashiCorp Vault または AWS Secrets Manager を設定
    • すべてのシークレットを保存時に暗号化

    • シークレットのローテーションポリシーを実装

    • [ ] コンプライアンス

    • 転送時と保存時のデータ暗号化
    • 監査ロギングを有効化
    • GDPR/CCPA コンプライアンスを検証
    • セキュリティスキャンを完了

    7. バックアップと回復

    自動バックアップスクリプト

    #!/bin/bash
# backup.sh

# Configuration
BACKUP_DIR="/backups"
S3_BUCKET="s3://ralph-backups"
DATE=$(date +%Y%m%d_%H%M%S)
RETENTION_DAYS=30

# Database backup
pg_dump $DATABASE_URL | gzip > $BACKUP_DIR/db_$DATE.sql.gz

# Application data backup
tar -czf $BACKUP_DIR/data_$DATE.tar.gz /app/data

# Upload to S3
aws s3 cp $BACKUP_DIR/db_$DATE.sql.gz $S3_BUCKET/db/
aws s3 cp $BACKUP_DIR/data_$DATE.tar.gz $S3_BUCKET/data/

# Clean old backups
find $BACKUP_DIR -name "*.gz" -mtime +$RETENTION_DAYS -delete
aws s3 ls $S3_BUCKET/db/ | while read -r line; do
  createDate=$(echo $line | awk '{print $1" "$2}')
  createDate=$(date -d "$createDate" +%s)
  olderThan=$(date -d "$RETENTION_DAYS days ago" +%s)
  if [[ $createDate -lt $olderThan ]]; then
    fileName=$(echo $line | awk '{print $4}')
    aws s3 rm $S3_BUCKET/db/$fileName
  fi
done

    パフォーマンスの最適化

    キャッシュ戦略

    # cache_config.py
from functools import lru_cache
import redis
import json

class CacheManager:
    def __init__(self, redis_url):
        self.redis = redis.from_url(redis_url)

    def cache_result(self, key, value, ttl=3600):
        """Cache result with TTL"""
        self.redis.setex(
            key,
            ttl,
            json.dumps(value)
        )

    @lru_cache(maxsize=1000)
    def get_cached(self, key):
        """Get cached value"""
        value = self.redis.get(key)
        return json.loads(value) if value else None

        'database': check_database(),
        'redis': check_redis(),

    サポートと保守

    SLA の目標

    • 稼働率: 99.9%（月あたり 43.8 分のダウンタイム）
    • 応答時間: p95 で 500ms 未満
    • エラー率: 0.1% 未満
    • 復旧時間: 4 時間未満

    オンコールの手順

    1. PagerDuty 経由でアラートを受信
    2. 既知の問題についてランブックを確認
    3. 深刻度と影響を評価
    4. 修正または回避策を実装
    5. インシデントを記録
    6. 必要なら事後分析
