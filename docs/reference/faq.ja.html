    よくある質問

    一般的な質問

    Ralph Orchestrator とは？

    Ralph Orchestrator は、Ralph Wiggum テクニック — AI エージェントを使った自律的なタスク 完了のための、単純でありながら効果的なパターン — の実装です。タスクが完了とマークされるか 上限に達するまで、プロンプトファイルに対して AI エージェントを継続的に実行します。

    なぜ「Ralph Wiggum」と呼ばれるのか？

    このテクニックは、シンプソンズのキャラクター Ralph Wiggum にちなんで名付けられました。 彼の台詞「僕が英語で失敗する？そんなの不可能だい！」は、予測不能な世界における決定的な 失敗の哲学を体現しています。このシステムは成功するまで挑み続け、「不可能」を受け入れます。

    誰が Ralph Orchestrator を作ったのか？

    Ralph Wiggum テクニックは Geoffrey Huntley によって 考案されました。この実装は、彼の概念の上に、複数エージェントのサポート、チェックポイント、 包括的なテストなどの追加機能を築いています。

    どの AI エージェントをサポートしているか？

    Ralph Orchestrator は現在、次をサポートします。

    • Claude（Anthropic Claude Code CLI）
    • Gemini（Google Gemini CLI）
    • Q Chat（Q CLI ツール）

    システムは利用可能なエージェントを自動検出し、最適なものを自動的に選択できます。

    インストールとセットアップ

    3 つの AI エージェントすべてをインストールする必要があるか？

    いいえ、少なくとも 1 つの AI エージェントがインストールされていれば十分です。Ralph は どのエージェントが利用可能かを自動検出し、それに応じて使います。

    AI エージェントはどうインストールするのか？

    # Claude
npm install -g @anthropic-ai/claude-code

# Gemini
npm install -g @google/gemini-cli

# Q Chat
# https://github.com/qchat/qchat の手順に従う

    システム要件は？

    • OS: Linux、macOS、または Windows（WSL 付き）
    • Python: 3.9 以上
    • Git: 2.25 以上
    • メモリ: 最低 4GB、推奨 8GB
    • ストレージ: 20GB の空き容量

    Ralph を Docker で実行できるか？

    はい！Dockerfile が提供されています。

    docker build -t ralph-orchestrator .
docker run -v $(pwd):/workspace ralph-orchestrator

    使い方の質問

    Ralph がいつ完了したかどう分かるか？

    Ralph は次のときに停止します。

    1. 最大イテレーションに到達する（既定: 100）
    2. 最大実行時間を超過する（既定: 4 時間）
    3. コスト上限に到達する（既定: $50）
    4. 連続エラーが多すぎる
    5. 完了マーカーが検出される
    6. ループ検出が発動する（反復的な出力）

    タスク完了をどう知らせるか？

    PROMPT.md にチェックボックスマーカーを追加します。

    - [x] TASK_COMPLETE

    Ralph はこのマーカーを検出し、直ちにオーケストレーションを停止します。これにより、AI エージェントはイテレーション上限だけに頼るのではなく「完了した」と知らせることができます。

    重要: マーカーはプレーンテキストではなく、チェックボックス形式（- [x] または [x]）でなければなりません。

    何がループ検出を発動させるか？

    ループ検出は、現在のエージェント出力が最後の 5 つの出力のいずれかと（ファジー文字列マッチ を使って）90% 以上類似したときに発動します。これは、エージェントが本質的に同じ応答を 繰り返す無限ループを防ぎます。

    よくある発動要因:

    • エージェントが同じタスクで行き詰まる
    • 似たアプローチの間で振動する
    • 一貫した API エラーメッセージ
    • プレースホルダーの「まだ作業中」の応答

    発動すると、次が表示されます: WARNING - Loop detected: 92.3% similarity to previous output

    ループ検出を無効にできるか？

    ループ検出は直接無効にできませんが、非常に類似した出力（90% 以上のしきい値）でのみ発動 します。誤検出を避けるには:

    1. エージェントの出力にイテレーション固有の詳細を含める
    2. イテレーションごとに変わる進捗インジケータを追加する
    3. エージェントが同じサブタスクで行き詰まっていないか確認する
    4. さまざまな応答を促すようプロンプトを洗練する

    詳細なドキュメントは ループ検出 を参照してください。

    PROMPT.md には何を書くべきか？

    測定可能な成功基準を伴う、明確で具体的な要件を書きます。次を含めます。

    • タスクの説明
    • 要件のリスト
    • 成功基準
    • 入出力の例（該当する場合）
    • ファイル構成（複雑なプロジェクトの場合）

    通常、何回のイテレーションがかかるか？

    これはタスクの複雑さによって異なります。

    • 単純な関数: 5〜10 イテレーション
    • Web API: 20〜30 イテレーション
    • 複雑なアプリケーション: 50〜100 イテレーション

    Ralph が停止したら再開できるか？

    はい！Ralph は状態を保存し、中断したところから再開できます。

    # Ralph は最後の状態から自動的に再開する
ralph run

    進捗をどう監視するか？

    # 状況を確認する
ralph status

# リアルタイムで監視する
watch -n 5 'ralph status'

# ログを表示する
tail -f .agent/logs/ralph.log

    設定

    既定のエージェントをどう変えるか？

    ralph.json を編集します。

    {
  "agent": "claude" // または "gemini", "q", "auto"
}

    またはコマンドラインを使います。

    ralph run --agent claude

    カスタムのイテレーション上限を設定できるか？

    はい、複数の方法で:

    # コマンドライン
ralph run --max-iterations 50

# 設定ファイル（ralph.json）
{
  "max_iterations": 50
}

# 環境変数
export RALPH_MAX_ITERATIONS=50

    チェックポイント間隔とは？

    チェックポイント間隔は、Ralph が進捗を保存するために Git コミットを作成する頻度を決めます。 既定は 5 イテレーションごとです。

    Git 操作をどう無効にするか？

    ralph run --no-git

    または設定で:

    {
  "git_enabled": false
}

    トラブルシューティング

    なぜタスクが完了しないのか？

    よくある理由:

    1. タスクの説明が不明瞭
    2. 要件が単一のプロンプトには複雑すぎる
    3. エージェントが形式を理解していない
    4. リソースや依存が欠けている

    Ralph が同じエラーに繰り返し当たる

    次を試してください。

    1. タスクを単純にする
    2. PROMPT.md に明確化を加える
    3. 別のエージェントを使う
    4. 特定の問題を手作業で修正する

    API コストをどう減らすか？

    1. より効率的なエージェントを使う（Q は無料）
    2. 最大イテレーションを減らす
    3. イテレーションを減らすためより明確なプロンプトを書く
    4. 再起動ではなくチェックポイントからの回復を使う

    Ralph をオフラインで使えるか？

    いいえ、Ralph は AI エージェントの API と通信するためにインターネットアクセスを必要と します。ただし、互換性のある CLI ラッパーを作れば、ローカルの AI モデルを使えます。

    高度な使い方

    カスタムエージェントで Ralph を拡張できるか？

    はい！Agent インターフェースを実装します。

    class MyAgent(Agent):
    def __init__(self):
        super().__init__('myagent', 'myagent-cli')

    def execute(self, prompt_file):
        # Your implementation
        pass

    複数の Ralph インスタンスを実行できるか？

    はい、ただし競合を避けるため異なるディレクトリで:

    # ターミナル 1
cd project1 && ralph run

# ターミナル 2
cd project2 && ralph run

    Ralph を CI/CD に統合するには？

    # GitHub Actions の例
- name: Run Ralph
  run: |
    ralph run --max-iterations 50 --dry-run

- name: Check completion
  run: |
    ralph status

    Ralph はプロジェクト外のファイルを変更できるか？

    既定では、Ralph は現在のディレクトリ内で作業します。安全のため、システムファイルや プロジェクトディレクトリ外のファイルを変更しないように設計されています。

    ベストプラクティス

    良いプロンプトとは？

    良いプロンプトは次のとおりです。

    • 具体的: 明確な要件と制約
    • 測定可能: 定義された成功基準
    • 構造化: セクションで整理されている
    • 完全: 必要な情報がすべて含まれている

    PROMPT.md を Git にコミットすべきか？

    はい！プロンプトをバージョン管理して次を行います。

    • 要件の変更を追跡する
    • チームメンバーと共有する
    • 結果を再現する
    • プロンプトライブラリを構築する

    どのくらいの頻度で Ralph を確認すべきか？

    典型的なタスクでは:

    • 最初の 5 イテレーション: 注意深く見守る
    • 5〜20 イテレーション: 5 分ごとに確認する
    • 20 イテレーション以上: 15 分ごとに確認する

    いつ手作業で介入すべきか？

    次のときに介入します。

    • 同じエラーが 3 回以上繰り返す
    • 進捗が 10 イテレーション以上停滞する
    • 出力が要件から逸脱する
    • リソース使用が過剰である

    コストとパフォーマンス

    Ralph の実行にいくらかかるか？

    タスクあたりの概算コスト:

    • 単純な関数: $0.05〜0.10
    • Web API: $0.20〜0.30
    • 複雑なアプリケーション: $0.50〜1.00

    （エージェントと API の価格により異なる）

    どのエージェントが最も速いか？

    一般的に:

    1. Q: 最も速い応答時間
    2. Gemini: バランスの取れた速度と能力
    3. Claude: 最も高性能だが遅い

    実行をどう高速化できるか？

    1. より単純なプロンプトを使う
    2. コンテキストサイズを減らす
    3. より速いエージェントを選ぶ
    4. システムリソースを増やす
    5. 不要な機能を無効にする

    Ralph はレート制限に対応するか？

    はい、Ralph は次でレート制限を扱います。

    • 指数バックオフ
    • リトライロジック
    • エージェントの切り替え（複数利用可能な場合）

    セキュリティとプライバシー

    私のコードは AI プロバイダに送られるか？

    はい、PROMPT.md と関連ファイルの内容は AI エージェントの API に送られます。次のような機微な データは決して含めないでください。

    • API キー
    • パスワード
    • 個人情報
    • 専有のコード

    機微な情報をどう保護するか？

    1. 秘密情報には環境変数を使う
    2. 機微なファイルを .gitignore に追加する
    3. 実行前にプロンプトを見直す
    4. ローカル開発用の認証情報を使う
    5. 生成されたコードを監査する

    Ralph は私のシステムにアクセスできるか？

    Ralph は AI エージェントを、次を伴うサブプロセスで実行します。

    • タイムアウト保護
    • リソース上限
    • 作業ディレクトリの制限

    ただし、エージェントはコードを実行できるため、常に出力を見直してください。

    本番サーバーで Ralph を実行しても安全か？

    推奨されません。Ralph は開発環境向けに設計されています。本番では、Ralph をローカルで使い、 テスト済みのコードをデプロイしてください。

    コミュニティとサポート

    バグをどう報告するか？

    1. GitHub の既存の issue を確認する
    2. 次を含む詳細なバグ報告を作成する: - Ralph のバージョン - エラーメッセージ - 再現手順 - システム情報

    Ralph にコントリビュートできるか？

    はい！コントリビューションを歓迎します。

    • バグ修正
    • 新機能
    • ドキュメントの改善
    • エージェント統合

    ガイドラインは CONTRIBUTING.md を参照してください。

    どこで助けを得られるか？

    • GitHub Issues: バグ報告と機能要望
    • GitHub Discussions: 質問とコミュニティの助け
    • Discord: コミュニティとのリアルタイムチャット

    商用サポートはあるか？

    現在、Ralph Orchestrator はコミュニティがサポートするオープンソースソフトウェアです。 商用サポートは将来提供される可能性があります。
