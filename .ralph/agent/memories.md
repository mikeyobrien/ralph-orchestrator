### mem-1790118737-5d99
> Removing an execve of a generated script by handing the file to the interpreter (sh "$script" "$@" instead of exec "$script" "$@") removes the ETXTBSY class, because ETXTBSY is execve-only. It is not semantics-neutral, so verify four things before accepting it: (1) the script's shebang interpreter equals the interpreter named in the new call, else the language changes; (2) no generated script reads $0, since sh script sets $0 to the script path as exec did but some callers rely on the parent's argv0; (3) no test or caller asserts signal termination (.signal()/ExitStatusExt), because a child shell converts a killed script into exit 128+signal; (4) the exit status still propagates as the shell's last command and non-zero codes are still asserted. Measured in crates/ralph-core/src/testing/fake_autoloop.rs at c390411: scripts are #!/bin/sh, no $0 read, no signal assertions, supports_nonzero_exit_and_replays_last_invocation asserts 7 and 3; two real /bin/sh dispatchers against one held write descriptor gave exec arm exit 126 'Text file busy' and sh arm exit 0.
